XCP-HL yum repository: xoa-proxy

Signed RPM repository for the XOA deploy proxy. Built for XCP-ng 8.3.

This site serves a yum-resolvable repository containing every released build of the xoa-proxy package, so an installed XCP-HL host can update in place instead of reinstalling from the ISO. Upgrading restarts the xoa-proxy service automatically.

Add the repository

On an XCP-ng 8.3 host, as root:

curl -o /etc/yum.repos.d/xcp-hl-xoa-proxy.repo \
  https://vagrantin.github.io/xoa-proxy/xcp-hl-xoa-proxy.repo

rpm --import https://vagrantin.github.io/xoa-proxy/xcp-ng-ce-public.asc

yum clean all
yum check-update xoa-proxy

Update

yum update xoa-proxy

The five most recent releases are kept, so you can list what is available and roll back within that window:

yum --showduplicates list xoa-proxy
yum downgrade xoa-proxy-<version>

Verification

The repository metadata (repodata/repomd.xml) carries a detached armored signature from the XCP-ng Community Edition signing subkey, and repo_gpgcheck=1 in the .repo file above verifies it on every run. Because the signed repomd.xml records a SHA-256 of primary.xml, which in turn records a SHA-256 of every package, that one signature covers the integrity of everything you download.

Per-package signature checking is off (gpgcheck=0), and that is deliberate. The RPMs are signed by a GPG signing subkey, but rpm 4.11 on XCP-ng 8.3 dom0 (CentOS 7) registers only the primary key when importing, so it reports NOKEY for a subkey-made signature. This is the same trust model apt uses: the release file is signed, individual packages are not.

Signing subkeys expire 2027-05-10. After that date, signature verification will fail until the subkeys are extended and xcp-ng-ce-public.asc is refreshed here and re-imported on hosts.
